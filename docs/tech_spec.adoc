== Введение

Документ описывает технические детали реализации проекта *E-Commerce Data Pipeline* и предназначен для сопровождения кода, обновления зависимостей, настройки окружения и автоматизации пайплайна.

== 2. Конфигурация и режимы запуска

[source,yaml]
----
paths:
  raw_file: data/raw/ecommerce_behavior.csv
  staging_dir: data/staging
  staging_file: data/staging/cleaned_data.parquet
  mart_dir: data/mart

mode:
  fast_test: true  # ограниченный режим для тестов
----

=== Описание параметров

- **raw_file** — путь до исходного CSV;
- **staging_dir** — директория для промежуточных parquet-файлов;
- **mart_dir** — конечные витрины данных;
- **fast_test** — при `true` пайп обрабатывает 100k строк (для тестирования).

== 3. Описание модулей

|===
| Модуль | Назначение | Входные данные | Выходные данные

| `load_raw.py`
| Проверяет наличие CSV, при отсутствии загружает с Kaggle
| Kaggle dataset / локальный CSV
| `data/raw/ecommerce_behavior.csv`

| `clean_staging.py`
| Очищает данные чанками, нормализует поля, сохраняет parquet
| CSV
| `data/staging/cleaned_data.parquet`

| `create_marts.py`
| Формирует витрины (4 таблицы)
| Parquet
| `data/mart/*.csv`

| `main.py`
| Управляет пайплайном, логирует этапы
| Конфигурация
| Логи выполнения

| `utils.py`
| Загружает конфиг, настраивает логирование
| YAML
| Python объекты
|===

== 4. Пайплайн выполнения

[source,bash]
----
python scripts/main.py
----

Основная последовательность:

. Проверка исходного CSV (`load_raw.py`)
. Очистка и нормализация (`clean_staging.py`)
. Создание витрин (`create_marts.py`)
. Логирование и завершение

== 5. Логирование

Файл логов: `pipeline.log`

Пример вывода:
----
2025-10-27 22:47:32,635 [INFO] 🚀 Запуск полного пайплайна
2025-10-27 22:47:44,835 [INFO] 📦 Обработка чанка #1 (100000 строк)
2025-10-27 22:49:10,122 [INFO] ✅ Очистка завершена, записано 485000 строк
----

=== Уровни логирования
- `[INFO]` — нормальные этапы
- `[WARNING]` — неполные чанки, NaN, подозрительные данные
- `[ERROR]` — сбой или отсутствие файла
- `[DEBUG]` — отладка при интеграции с S3

== 7. Поддержка S3 (на будущее)

После перехода на AWS/MinIO:

*Добавить в `requirements.txt`:*
[source,txt]
----
boto3
s3fs
----

*Обновить `config.yaml`:*
[source,yaml]
----
storage:
  type: s3
  bucket: my-bucket
  region: eu-central-1
----

*Заменить чтение/запись:*
[source,python]
----
df.to_parquet("s3://my-bucket/data/staging/cleaned_data.parquet")
----

== 8. Автоматизация пайплайна

Планируется внедрение Airflow / Prefect для автоматизации ETL-процессов.

*Основной DAG:*
[source,text]
----
load_raw → clean_staging → create_marts
----

*Расположение файла:*
[source,bash]
----
dags/pipeline_dag.py
----

*Задачи DAG:*
- Airflow `PythonOperator`
- Логирование через `XCom`
- Ретрай: 2 попытки, интервал — 10 минут
- Автоматическая метка времени запуска
- Статусы выполнения в логах и мониторинге

== 11. Примечания

- Все пути должны быть относительными к корню проекта
- Логи и результаты не коммитятся (см. `.gitignore`)
- Конфиденциальные данные (ключи S3, токены Kaggle) не хранятся в репозитории
- Любое изменение модулей сопровождается обновлением документации и зависимостей
- Для новых участников проекта предусмотрен `README.adoc` с инструкцией по запуску локально и в S3
